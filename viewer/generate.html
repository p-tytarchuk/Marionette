Marionette generator

Type what the character should do. A latent diffusion model makes a motion, it is put on the character you pick (IK, then the retargeter) and played on the right. character browser →

Prompt

"a small brown dog doing a backflip" is split into the look (“a small brown dog”, matched against rest-pose portraits of all characters with CLIP) and the motion (“does a backflip”, generated). With no shape words (“An object walks forward.”) the character chosen below is used. Only existing characters are returned (no new bodies). The model was trained on captions like "An object performs a backflip." Rewriting turns "person does a back flip" into that form: the default front end does it with word lists and rules (no language model; the "shape" words are split off first), the LLM option uses Qwen2.5-1.5B (better on garbled wording) and made reworded prompts match about 4-9 points better in tests. Untick to send the text as typed.

Character

Sampler

Zeroes the generated sideways velocity and yaw rate, so the character moves along one straight line. Tested on flips, walk and run: nothing else in the motion changes (the quality rates were identical), the path deviation drops to 0. Leave it off for actions that turn ("walks in a circle", cartwheels). Guidance 1-6: higher follows the prompt harder but gives less varied, shorter, faster motion (2 is the tested default). Auto = walk setting for "walks", run setting for "runs / jogs / sprints", plain for everything else. Smooth = low-pass (frames) on the generated limbs, removes joint jumps in fast moves such as flips (0 = off).

Runtime

Runs the neural part (CLIP text encoder, the 50-step diffusion sampler, the decoder) the way a phone would: ONNX Runtime on the CPU with the int8 denoiser and decoder (data/mobile, 289 MB here, about 98 MB on a phone), and shows how long each step takes. Measured on this computer; the phone figure is that time times the slowdown factor, which is an assumption (not measured on a phone). The IK, quality gate and retargeter are still Python here and would be native code on a phone. Walk and run use the desktop sampler (their speed constraint is not ported). Ticking the box creates the sessions in the background (about 1 s, not counted). With the box unticked the same timing breakdown is shown for the desktop (torch) runtime.

Quality gate

Plain mode (flips, kicks, jumps, rolls…) draws up to this many candidates and keeps the first that is smooth (at most 1 joint step over 60°, none over 100°) and, for a flip prompt, completes the turn (hips pitch range at least 300°) and, if ticked, ends upright (body-up axis within 37° of vertical over the last 8 frames). If none passes, the best candidate is used and the result says so. About 8-9% of single flip samples pass all three, so raise Tries for flips (16 tries about 3 s). Walk and run modes have no gate; 1 = gate off.
