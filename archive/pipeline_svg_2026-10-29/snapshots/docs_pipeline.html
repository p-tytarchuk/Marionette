Marionette: where we are

Text prompt in, animated creature out. Three branches are being built side by side: a 3D motion generator, a way to get the character (shape and skeleton), and a Lottie / 2D branch. Each box below is one step; click it for its manual.

Pipeline map

The original plan against today

From notes/Text → Rigged, Animated Creature Pipeline Plan.md (19 Oct 2026): four parts, two of them trained on your data.

Plan partIn the planNow
1 Text encoderFrozen, downloadedDone. CLIP ViT-B/32 text tower, every caption embedded. For the phone it is the biggest model (254 MB fp32, 63 MB weight-only int8) and its tokenizer is not ported.
2 Shape generatorEmbedding + class → shape code that deforms a template mesh; learned joint regressor places the skeletonNot built. Replaced by retrieval of an existing character (pilot). Anymate (pretrained) stands in for the joint regressor and skin weights (pilot, geometry only).
3 Motion generatorEmbedding + class + shape code → joint rotations on the class templateWorking, being tuned. Built differently: a latent diffusion model makes a motion for a human proxy skeleton, then a rule-based retargeter plays it on the chosen body (no shape code is given to the model).
4 AssemblyApply motion to the skinned mesh, export GLBDone for characters that already exist (GLB clips, viewer).
On-deviceGalaxy S23 Ultra, 100–150 MB, under 2 sAudit only. Models export and match torch; about 2,300 lines of numpy/scipy glue have no phone version; nothing measured on a phone.
Added since(not in the plan)The Lottie / 2D branch (text → 2D animation), started 2026-10-26.

What to do next

Decisions only you can make

  1. The Lottie generator. Option A: train a text-conditioned model on the sine-fit tracks of the 42,568 clean candidates. Option B: reuse the 3D generator and convert its motion with motion_to_2d.py + bake_lottie.py, which needs 2D rig data that does not exist yet (data/side_view_animals/).
  2. Shape: retrieve or generate. Keep retrieval (works now, limited to 3,570 existing meshes) or build the plan's shape generator.
  3. Quadruped size policy (0.9 m for all quadrupeds at the moment).

Open work, roughly in the order the README lists it

  1. Flips: incomplete flips and deep-crouch endings remain; the retargeter adds spikes even to real flips.
  2. Quadruped data: 430 usable clips, 30% are "walk in place".
  3. Lottie model: train on all 69,585 tokenised clips (it samples 11,000), lower the 2D/3D domain gap.
  4. Phone: port the IK, smoothing and retarget code; tokenizer; measure on a real device.
  5. Evaluation: held-out sets are small; no perceptual metric, no user study, flips judged from stills.
